# 我的世界内网穿透怎么选：frp、虚拟局域网、云服务器开服，哪种能撑住长期朋友服？2C4G 够几个人？（附配置对照表）

想让朋友连上你自己电脑开的 MC 服务器，能走的路只有三条，但其中只有一条不受"房主关机"影响。

frp、MossFRP 这类端口穿透，和 ZeroTier、蒲公英这类虚拟局域网，做法都是把房主家那台电脑临时暴露到公网。云服务器开服换了一台不下线的机器来跑服务端，你关不关电脑跟服务器没关系。前者几十块都不用花，代价是房主一关机、一休眠、一断网，全队掉线；后者按月付费，机器在机房里 7×24 跑着。

分界线可以这么划。一两个朋友偶尔周末玩两小时、房主电脑能一直开着，免费的穿透或组网完全够用，不必买服务器。固定车队、要长期存档、要装插件模组、希望半夜也有人能摸进去种地，就该看云服务器这条。

下面把三条路线的成本结构、人数上限和失效边界摊开讲，再给一份按人数选配置的对照表和开服避坑清单。

## 三条路线到底差在哪

| 对比项 | 端口穿透（frp / MossFRP 类） | 虚拟局域网（ZeroTier / MCTier / 蒲公英类） | 云服务器 + 面板（雨云 + MCSM） |
| --- | --- | --- | --- |
| 房主电脑要不要一直开 | 要，穿透客户端也得常驻 | 要，房主下线全队断 | 不要 |
| 能否 24 小时在线 | 不能 | 不能 | 能，机器在机房 |
| 需要公网 IP 吗 | 不需要，走中转节点 | 不需要，走虚拟网 | 平台提供公网访问和端口 |
| 上手难度 | 中，要配穿透码和客户端 | 低到中，装客户端进同一房间 | 低，买完进面板点启动 |
| 成本结构 | 免费额度靠签到换，超出要充值 | 多数工具有免费设备数上限 | 按月或按量付费 |
| 典型失效场景 | 房主关电脑、穿透码过期、节点拥堵 | 房主关电脑、P2P 打洞失败走中转 | 配置买小了、端口没开对 |

这张表里最容易被忽略的是第一行。教程教你点完下一步、拿到连接地址就算完事，但没人提醒你：这条链路的终点是房主家那台机器。房主晚上关电脑睡觉，服务器就没了。

MCTier 这个基于 EasyTier 的开源组网工具在自己的说明里写得很直白：要 24 小时公开服，虚拟 LAN 仍绑定"房主电脑开机"，长期服更该用独立主机加面板服。做工具的人自己都这么说。

## 免费穿透并不是零成本：穿透码要花银币

以 MossFRP 的完整流程为例。注册登录后先看节点状态，然后创建穿透码，需要填三项：用哪个节点、多少带宽、用多少天。这一步会消耗银币或金币，来源是每日签到或充值。创建时间最低 3 天，之后可以给穿透码升配带宽或续天数。

带宽的参考值是 3 名玩家约消耗 1Mbps。反过来算，想带 6 个人就得往上加。

客户端操作不复杂：运行 `run.bat`，输入 `save 1 <你的穿透码>` 生成配置文件，再 `reload` 拿到连接地址，玩家在多人游戏里添加这个地址就能进。延迟高了就在网站上换个节点，重新配一次穿透码。停止穿透输入 `exit`。

所以"免费"的真实含义是"签到换额度"。想连续开一周，得提前攒够银币或者充值。另外穿透码不能泄露，拿到码的人能直接把流量引到你的机器上。

## 虚拟局域网解决了输 IP 的麻烦，没解决房主关机

ZeroTier、Tailscale、MCTier、蒲公英这类工具把几台机器拉进同一个虚拟网，玩家像在同一个局域网里直连，不用记公网 IP。MCTier 这类新产品还做了 MC 世界自动发现，能扫描队友开放的世界并注入到本机多人游戏列表，免去手输地址。

限制也要看清楚。蒲公英免费版房间最多 5 名成员，含房主本人。ZeroTier 免费约 25 台设备、Hamachi 免费仅 5 人这类数字来自第三方测评文章，官方政策会调整，用之前自己去官网确认一遍。

## 云服务器这条，钱花在了什么地方

雨云在这套方案里提供的是四样东西，跟"帮你管理 Minecraft"没关系：计算资源（CPU、内存、磁盘，决定能跑多少人、能开多大视距）、网络能力（公网访问、端口、带宽与延迟）、计费与生命周期（月付或按量、到期、续费、关机释放）、控制台（实例状态、到期时间、端口信息、面板入口）。

MCSM 面板则把开服拆成一件具体的事：一个实例 = 一个目录 + 一套启动命令 + 一组端口 + 一份配置。

面板里能干的事包括一键启动停止重启、崩溃后自动拉起、实时控制台直接敲 `op`、`whitelist`、`save-all`、在线上传下载和编辑 `server.properties`、给不同协作者分配不同权限。后一条很实用，朋友帮你运维不用把 SSH 账号到处发。

真正让服务器"能长期跑"的是三个计划任务，建议开服第一天就配上：

- **每日定时备份**。范围覆盖 `world/`、`world_nether/`、`world_the_end/` 加核心配置文件，保留最近 7–14 份，旧备份自动清理，不然磁盘很快被撑爆。
- **每日低峰定时重启**。小服也建议重启，选凌晨，重启前用任务广播提前 5 分钟和 1 分钟各提醒一次。
- **定时执行 `save-all`**。降低意外崩溃时的回档概率。

崩溃自动重启要配合重启冷却时间和最大重启次数，否则服务端一旦起不来就会陷入重启死循环，日志刷得飞快还找不到原因。

## 2C4G 够几个人：算力和带宽是两个瓶颈

按人数选配置，经验值大致是这样：

- **2C4G**：2–5 人轻度生存，插件少，视距别调太高
- **4C8G**：5–15 人，或中等插件量
- **8G 内存以上**：更多玩家、重插件、高视距、多模组需求

8G 以上多数朋友服用不上。多出来的内存是给模组和视距的，不是给人数的。一个 6 人原版生存服塞进 8C16G，性能余量全浪费在空转上。

另一条经常被搞混的瓶颈是房主的上行带宽。家庭宽带下行 300Mbps 的套餐，上行可能只有 30Mbps。联机时所有人的数据都从房主这边发出去，卡的是上行不是下行。上行 ≥30Mbps 时 3–5 人基本够用，只有个位数 Mbps 的话，人数一多必然卡。云服务器这条不存在房主上行的问题，但要看你买的套餐给了多少带宽，买的时候把这一项和内存一起看。

购买时四个选择点按重要性排：

1. **区域**。优先选离玩家近的，同样的配置，延迟差会让体验差很多。
2. **CPU 和内存**。按上面的档位来，别一步到位买大。
3. **计费模式**。固定计费适合长期稳定开服，动态计费适合测试和临时活动服，但要留意到期与关机策略，别让存档跟着过期一起没。
4. **磁盘空间**。10G 往往只是起步，世界存档会涨，备份也占空间，尤其是保留多份压缩包的情况。

买完在控制台能看到实例名称和 ID、运行状态、到期时间、TCP 和 UDP 端口信息，以及 MCSM 面板的入口链接。

## 开服前把这些坑填了

**系统版本**。CentOS 7 上安装 MCSM 会提示"操作系统版本过低，无法使用"。选 Ubuntu 24.04 LTS 或 CentOS 8 以上。习惯命令行的老手用 CentOS 7 也能跑，只是用不了面板。

**`online-mode=false` 的风险**。关掉正版验证后日志里会出现 OFFLINE/INSECURE MODE 提示，任何人都能用任意名字登录，包括你朋友的名字。冒名进来的人如果拿到了 op，存档就危险了。朋友私服也建议开白名单，只让可信的人进。

**换存档的两个坑**。替换的 `world` 文件夹名称必须和原来一致。如果你用非 root 用户跑服务（比如 `mcfabricuser`），替换后要把目录属主赋给这个用户，否则服务端写不进数据，直接起不来：

bash
sudo chown -R mcfabricuser:mcfabricuser /minecraft


**模组规则**。原版 `server.jar` 加不了模组，得装 Fabric 或 Forge。Fabric API 必须放进 `mods` 文件夹，不然其他模组不生效。服务端模组要本地和服务端各放一份且版本一致，客户端模组（小地图这类）只装在本地就行。

**性能参数**。`server.properties` 里把 `view-distance` 从默认 10 降到 6，`simulation-distance` 降到 4，对 TPS 的提升很直接，视觉上几乎察觉不到。内存长期超过 80% 就调大 `-Xmx`，但分配量不要超过物理内存的 50%，超了会被系统杀掉进程，表现就是玩着玩着闪退。

**面板安全**。管理员密码改到 16 位以上，别把面板账号当共享账号发。能改文件、能执行命令、能重启实例、能下载存档这四类权限风险最高，多人协作时尽量拆开授予。

## 连不上、卡、掉线，按这个顺序查

先分清是哪种"卡"，不然越查越乱：

- 只有我卡、别人不卡 → 问题在我的网络或电脑
- 所有人同一时刻一起卡 → 问题在服务端
- ping 很低但操作有延迟感 → 不是网络，是 TPS

然后按成本从低到高往下走。

**第一步，确认所有人都点了【马上联机】**。这是联机失败里出现频率最高的一条，人都在房间里，游戏里却谁也搜不到谁。

**第二步，查防火墙**。Java 版要放行的是 `javaw.exe`，不是游戏启动器。360、电脑管家、火绒这类安全软件有自己的拦截规则，排查时一并临时退出。公司网、校园网、酒店网常有限制，换个手机热点能快速判断是不是网络环境的问题。

**第三步，ping 一下**。让好友在自己电脑上跑：


ping 172.16.2.3 -n 20


地址换成房主的虚拟 IP。有回复且延迟低，说明虚拟网通了，问题在游戏设置或防火墙；全部超时说明虚拟网压根没打通；有回复但丢包，就是链路质量差。

**第四步，看连接类型**。客户端显示"转发"意味着 P2P 打洞没成功，走的是中转，能用但延迟高一档。让双方都换成家庭宽带、路由器开 UPnP，成功率会高不少。

**第五步，测房主的上行带宽**。顺手关掉后台吃上行的程序，云盘同步是最隐蔽的一个，它会在你不知情的时候把几十个 G 往外传。

**最后才动性能参数**。视距、实体数量、红石频率、内存分配，这些放到最后调。

上面涉及的延迟、带宽、内存、MTU 数值都是典型场景的经验值，网络环境、机器配置、游戏版本差异很大，以本地 ping 和游戏内 F3 实测为准。

## 所以你该选哪个

一个人数很少、房主能一直开机的临时局，用免费穿透或者组网工具就行，把省下的钱买奶茶。这类场景买服务器是真的浪费。

固定三五个人的长期生存服，从 2C4G 起步，配上面板做每日备份和凌晨重启，够用很久。玩到十来人、开始堆插件，再升 4C8G，这是最直观的一次提升。重模组整合包、二十人往上的群组服才需要考虑 8G 内存以上。

下单前最后确认两件事。区域选离玩家最近的那个，延迟是体感的第一指标。计费模式按用途选，长期稳定开服走固定计费，测试和临时活动服走动态计费，但一定要看清到期时间和关机后的数据保留策略。
